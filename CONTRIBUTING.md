# Contributing

## Ground rules

- Plain ASCII in code and docs. Terse technical English.
- `cargo fmt --all`, `cargo clippy --workspace --all-targets
  --all-features` with no warnings, `cargo nextest run --workspace
  --all-features` green. CI runs the same on Linux, macOS and Windows,
  with clippy from the current stable Rust and a build on the minimum
  supported version, 1.95.
  On a pull request the emulator tier and the Python decoder jobs run
  only for what the change touches (`tools/ci/changes.py`; the
  `changes` job's summary says why). The `ci:full` label runs
  everything.
- Every change that a user can see gets a line in `CHANGELOG.md`.
- No `unsafe` code. The one exception is `pydecode`, which crosses
  into Python; every block there says why it is sound.

## Performance

`cargo run --release --example trigger_bench` measures the host
software triggers (`SoftTrigger`, `SoftTriggerLogic`, the pre-trigger
buffer) in million samples per second, on fx2lafw-sized transfers.
A streaming driver that triggers on the host needs them faster than
its sample rate. Run it before and after a change to them; `--min`
fails a run below a rate, and a trigger that fires on data built so it
never should fails it too.

## Adding a driver

`docs/DRIVER_PORTING.md` has the shape of a driver, the transports,
the testing approach and the pitfalls met so far. Every driver ships a
replay fixture so it is tested without the hardware, and an entry in
`docs/DEVICES.md` saying what has been verified on which device.

## Compatibility with sigrok-cli

Outputs are compared with sigrok-cli byte for byte after the header
line. When adding an output or changing one, capture the reference with
sigrok-cli and put it in the test next to the command that produced it.
`tools/diffcli.sh --oracle` runs the documented flows through both tools,
with `--hw` for the attached hardware.

A change to a driver is checked with `sh tools/diffcli.sh --emu-model
MODEL`, which runs oxrok alone against the model's committed goldens on
the emulator ([docs/USB.md](docs/USB.md#emulation-over-usbip)). When
oxrok's output or transactions change on purpose, `EMU_BLESS=1` re-records
the goldens of the cases whose other checks pass, and the commit says why
they changed. `--oracle` brings sigrok-cli and libsigrok back for a new
port or for checking an upstream sigrok change.
